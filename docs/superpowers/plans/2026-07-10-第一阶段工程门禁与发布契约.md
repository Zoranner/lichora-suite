### 建立仓库质量检查入口

**Files:**
- Create: `scripts/check-quality.ps1`
- Modify: `README.md`
- Modify: `docs/development.md`

- [ ] **Step 1: 定义检查脚本的命令契约**

脚本提供 `-SkipRust`、`-SkipOverlay`、`-SkipUnity` 和 `-SkipPackaging` 开关；默认依次执行：

```powershell
cargo fmt --all -- --check
cargo clippy --all-targets --all-features -- -D warnings
bun test
bun run typecheck
bun run build
csharpier check <all tracked Unity C# files>
.\scripts\check-plugin-contract.ps1
```

每一步失败立即退出，输出命令名和失败阶段；Unity 检查只调用 CSharpier 和静态脚本，不启动 Editor。

- [ ] **Step 2: 实现 Rust、Bun 和 Unity 检查分支**

Rust 分支从仓库根目录执行 Cargo 命令；overlay 分支从 `packages/overlay` 执行 Bun 脚本；Unity 分支通过 `git ls-files 'hosts/unity-host/**/*.cs'` 收集已跟踪 C# 文件并传给 CSharpier，避免扫描 `Library` 或宿主生成目录。

- [ ] **Step 3: 补充文档入口**

在 `README.md` 和 `docs/development.md` 增加：

```powershell
.\scripts\check-quality.ps1
```

并明确该入口不启动 Unity Editor，不执行 Unity 生成项目编译。

- [ ] **Step 4: 静态检查脚本本身**

运行：

```powershell
Get-Content scripts/check-quality.ps1
```

确认脚本没有 `npm`、`npx`、`dotnet build`、`msbuild`、`Unity.exe`、`batchmode` 或 `BuildPipeline`。

### 建立 Unity 原生插件支持矩阵与 manifest

**Files:**
- Create: `hosts/unity-host/Plugins/plugin-manifest.json`
- Create: `scripts/check-plugin-contract.ps1`
- Modify: `hosts/unity-host/README.md`
- Modify: `docs/development.md`

- [ ] **Step 1: 编写支持矩阵 manifest**

manifest 至少记录每个插件的逻辑名、文件路径、平台、架构、P/Invoke 名称、发布状态、来源 crate 和 ABI 版本：

```json
{
  "schemaVersion": 1,
  "plugins": [
    {
      "name": "lichora_ipc_native",
      "path": "Plugins/Windows/lichora_ipc_native.dll",
      "platform": "Windows",
      "architecture": "x86_64",
      "dllImport": "lichora_ipc_native",
      "release": true,
      "sourceCrate": "lichora-ipc-native",
      "abiVersion": 2
    }
  ]
}
```

Linux 当前按 README 中的 `0.1.0` 支持声明记录为非 release，不能把当前限制改成已支持。

- [ ] **Step 2: 实现静态契约检查**

脚本验证：

- manifest JSON 可解析且字段完整；
- manifest 中声明的文件存在；
- 每个 `dllImport` 在 Unity C# 中存在；
- `build.ps1` 的复制目标包含 Windows native 插件；
- 对 Linux 非 release 插件，`.meta` 的平台状态与 manifest 一致；
- `package.json`、README 和 manifest 的包名/版本/平台声明一致。

检查失败时输出插件名和具体路径，不修改任何文件。

- [ ] **Step 3: 补齐插件来源和校验说明**

在 `hosts/unity-host/README.md` 增加 manifest 使用方式、构建来源、目标架构、ABI 版本含义和二进制校验流程。校验值若当前不能稳定生成，先记录“由发布流水线生成”，不能填虚假 hash。

- [ ] **Step 4: 运行静态契约检查**

运行：

```powershell

```

预期：所有已声明插件、P/Invoke 和平台状态一致；不能把 Unity Editor 导入结果写成验证结论。

- [ ] **Step 2: 增加 package check 脚本**

`check-package.mjs` 静态检查 `package.json` 的 `exports`、`files`、入口文件和 README 存在；脚本只使用 Node 内置模块，不生成发布物。

- [ ] **Step 3: 更新 Bun scripts**

`packages/overlay/package.json` 增加：

```json

  "check-package": "bun scripts/check-package.mjs",
  "check": "bun test && bun run typecheck && bun run check-package"
}
```

如果环境没有全局 `tsc`，应使用仓库已有工具或明确报告缺失，不使用 npm/npx 安装。
