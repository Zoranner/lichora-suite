# 自包含 overlay 单页设计

## 目标

为 Unity 手工联调生成一个无需开发服务器、无需运行时编译、可由 `local://` 直接加载的单 HTML 页面。该页面必须包含最新版 `@lichora/overlay` 行为，包括由 Chromium 生成最终 alpha mask。

## 事实源

`packages/overlay/src` 是 ownership 扫描、发布和 alpha mask 行为的唯一源码。Unity 测试页不再手写或维护另一套 ownership 实现。

测试页的布局和交互保留为独立入口代码。构建时由 Bun 将入口及其 overlay 依赖打包，并内联到 HTML 模板中，最终只产生一个 HTML 文件。

## 生成链路

生成命令位于 `packages/overlay`，使用仓库既有 Bun 工具链：

```text
overlay 源码 + 测试页入口 + HTML 模板
                |
                v
       自包含 overlay-pass-map.html
                |
                v
BrowserRenderer/BrowserAssets/demo/overlay-pass-map.html
```

生成结果不得引用 `.ts`、外部 JavaScript 文件、开发服务器或 `node_modules`。页面加载后直接调用 overlay `enable()`，继续通过现有 ownership bridge 发布输入归属数据。

## 运行边界

Unity 继续使用：

```text
local://BrowserAssets/demo/overlay-pass-map.html
```

本次不修改 Rust/CEF 运行时，不重新构建 `lichora.exe`。CEF 已有透明 OSR 帧链路继续传递 Chromium 输出的 alpha；Unity 直接消费 BrowserAlpha。

## 同步边界

`lichora-suite` 保存源码、模板、生成脚本和可复现的本地生成结果。`BrowserRenderer` 中的 HTML 是供 Unity 直接运行的同步产物。

同步必须基于 BrowserRenderer 当前文件进行，保留其现有页面布局和用户未提交改动。生成或同步前后需要检查 diff，不能覆盖无关内容。

## 验证

验证分为三层：

- 先以失败测试证明当前生成页不包含 Chromium alpha mask，再实现生成链路并使测试通过。
- 运行 overlay 的 Bun 测试、类型检查和包契约检查，确认 SDK 行为与生成入口一致。
- 对生成后的单 HTML 做浏览器级检查，确认页面可独立加载、根元素获得 SVG mask、Host 圆角区域输出透明 alpha，并确认文件不包含外部脚本依赖。

Unity Editor 内实际合成效果由用户侧 Play 验证；本仓库流程不启动 Unity Editor。
